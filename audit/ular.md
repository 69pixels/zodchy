## Анимации и поведение

Всё написано вручную, без библиотеки. Основной механизм — один `requestAnimationFrame`-цикл `renderScroll` на scroll-событии, который считает прогресс и пишет CSS-переменные.

| Эффект | Где | Реализация | Будущий пресет |
|---|---|---|---|
| Вход hero (текст, CTA, арт) | Hero | CSS `@keyframes enter` / `art-in`, задержки 0 / .1 / .2 с | `reveal-up` + `data-motion-delay` |
| Заливка слов по скроллу | Миссия | `--fill` на каждом слове, `background-clip:text` | `scroll-text-fill` |
| Pinned-сцена со сменой слайдов | Ценности | sticky + прогресс `p` → индекс 0–3, переходы opacity | `scroll-pin-steps` |
| Pinned-раскрытие | Направления | `--p`, `--r`, `--c`: подъём фото, смена цвета текста, `inert` на карточках до открытия | `scroll-pin-reveal` |
| Кроссфейд фонов | Направления | двойной слой `is-active` / `is-prev`, ждём `img.decode()` | входит в `scroll-pin-reveal` |
| Появление описания/сетки при смене вкладки | Направления | Web Animations API, opacity 260 мс | `fade-swap` |
| Прогрессивный blur | Ценности, Направления | 4 слоя `backdrop-filter` с масками | компонент-утилита `progressive-blur` |
| Скрытие/показ хедера | Header | `is-hidden` по направлению скролла | `header/hide-on-scroll` |
| Поле отталкивания точек | Карта | canvas, lerp 0.14, радиус 150 × scale, ≤9 px | `dots-field` (кастомное, не пресет) |
| Панель бренда | Панель | transform 320 мс | `slide-panel` |
| Hover кнопок/карточек | везде | CSS transition, `translateY(-2…-5px)` | токен hover-lift |

**Reduced motion:** поддержан везде. `@media (prefers-reduced-motion)` отключает все CSS-анимации, миссия заливается сразу (`--fill:100%`), «Ценности» и «Направления» превращаются в статичные блоки, видео ставится на паузу, JS-эффекты проверяют `reducedMotion.matches`. Это уже хороший образец для пресетов.

## Токены в коде

Токены есть, но их мало и они смешаны с «магией»:

- **Есть:** `--orange:#ff4600`, `--ink:#333130`, `--grey:#535353`, `--soft:#f1f0ea`, `--yellow:#ffce63`, `--gutter`, `--gap`, `--u` (масштаб `100vw/1440`), `--s`, `--stage-height`.
- **Принцип размеров:** почти все размеры написаны как `calc(N * var(--u))`, то есть масштабируются линейно от макета 1440. На мобильных `--u:1px`. Это обходит адаптивность через масштаб, а не через брейкпоинты, и расходится с принципом AGENTS.md (токены темы). Для стартера нужен нормальный набор шкал (spacing, type, radius) + контейнерные брейкпоинты 1440 / 1024 / 768 / 375.
- **Хардкод:** `#e94000` (hover), `#b83813` (ошибка), `#34444a` (фон values), `#514d3e`, `#e5e4e0`, радиусы 20/24/28/32 px, тайминги `.2s / .25s / .33s / .45s`, кубические кривые. Всё это должно стать токенами.
- **Шрифты:** Aeonik (коммерческий, OTF) и Roboto Mono; `font-synthesis:none`, `ss02`. Лицензия Aeonik — `TODO(human)`: проверить право на веб-использование и конвертировать в WOFF2.

## Костыли и риски

1. **Данные и контент в JS.** `data.js` и `copy.js` (ключи вида `2647:227` — это id узлов Figma) хранят весь текст. Для Astro это должно стать контент-коллекциями или типизированными данными. `copy.js` с id Figma вместо смысловых ключей — признак автогенерации из дизайна.
2. **Вся разметка секций «Направления», «Ценности», «Новости», «Карта» строится в JS через `innerHTML`.** Без JS страницы нет (есть `noscript`-блок, но содержимое пустое), SEO и первая отрисовка страдают. В Astro это должно рендериться на сервере.
3. **Масштабирование через `calc(N * var(--u))`** (см. выше) и пересчёт `scale` в JS. Ломается при нестандартных зумах и совпадении ширин; `body{min-width:1024px}` на десктопе.
4. **Абсолютное позиционирование логотипов с кропами по пикселям** (`allur-crop` и др.) — ручная подгонка. Нужны нормализованные SVG-логотипы в едином боксе.
5. **Сцена «Направления» держится на подсчёте высот**: `reserveCompanyHeights` перебирает все вкладки, подменяя `innerHTML`, чтобы измерить максимум. Хрупко при смене шрифтов/контента.
6. **Scroll-логика на `scroll` + `getBoundingClientRect` в каждом кадре** (без IntersectionObserver/ScrollTrigger). Работает, но смешивает чтение и запись layout; GSAP ScrollTrigger заменит и pin, и прогресс.
7. **`window.scrollTo(behavior:'instant')` для выбора ценности** — «перематывает» страницу по клику на таб; объяснимо дизайном (pinned), но нужно оформить как поведение пресета.
8. **Одна глобальная `styles.css` с «патчами» в конце** (`/* v8.1 */`, повторные определения `.map-art`, `.logo-stage`, второй `@media (prefers-reduced-motion)`) — следы итераций. При переносе нужно разбить по секциям.
9. **Форма не отправляется** (честно сообщает об этом). Бэкенда нет — решение за клиентом (`TODO(human)`).
10. **Юр. документы — заглушки** (`Privacy Policy`, `Terms of Use` открывают диалог «документ не опубликован»).
11. **Языковой переключатель — заглушка** (только RU).
12. **Тяжёлые ассеты**: 9,5 МБ, PNG для крупных фото, видео 2,7 МБ; нет `srcset`/AVIF/WebP. Hero-видео без постера.
13. **Хостинг:** репозиторий `ular` содержит удалённые и заново загруженные `home-v8` (история «Delete home-v8 directory» / «Add files via upload») — версии теряются; в новом процессе это должно быть ветками.
14. **Мобильная вёрстка живёт внутри одного `@media(max-width:1023px)` блока на ~80 строк**, часть значений зашита под 375 px (`width:343px`, `top:61px`, `height:702px`). Планшетная ширина (768–1023) специально не проработана — отдельного макета в Figma нет.
15. **Доступность — сильная сторона**: skip-link, ARIA-вкладки с клавиатурой, focus trap в панели, `inert`, `aria-live`, reduced motion. Это нужно сохранить как стандарт библиотеки.
