# AGENTS.md — правила работы агентов в Zodchy

Этот файл — источник истины для всех агентов (Claude Code, Codex). `CLAUDE.md` его импортирует. Меняем правила только здесь.

## Контекст

Zodchy — система студии для производства лендингов: Figma → spec → прототип (low/hi-fi) → продакшн на Astro. Подробности и история решений — `docs/HANDOFF.md`. Текущие задачи — `backlog/BACKLOG.md`.

## Принципы

1. **Прототип = ранняя версия продакшна.** Low-fi, hi-fi и прод — один код на разных стадиях (wireframe-тема → брендовая тема → контент/SEO/перф).
2. **Spec — контракт.** Агент реализует то, что описано в `spec/`. Если информации не хватает — дописывает черновик в spec и помечает `TODO(human)`, а не додумывает молча.
3. **Сначала библиотека.** Перед созданием секции/анимации проверь `src/sections/` и `src/motion/`. Новое создаётся только если в spec стоит `NEW` или ничего не подходит — и тогда помечается кандидатом в библиотеку.
4. **Figma читаем экономно.** Сначала `get_metadata` (структура), затем точечно `get_screenshot` / `get_design_context` по node-id нужного фрейма. Результат кэшируется в `design/`; повторно в Figma ходим только за изменившимися фреймами.
5. **Токены, а не значения.** Цвета, шрифты, отступы, радиусы, тайминги — только через CSS-переменные темы. Хардкод значений из Figma запрещён.

## Git

- Одна задача — одна ветка — один или несколько небольших коммитов. Коммит после каждого законченного шага.
- Крупная переделка или версия для клиента — отдельная ветка (`v2-…`, `review/…`), старая версия остаётся доступной.
- Не переписывать историю общих веток, не делать force-push в `main`.
- Решения, отличные от spec, записывать в `DECISIONS.md` проекта (дата, что решили, почему).

## Конвенции

- Секции: `src/sections/<тип>/<вариант>/` — компонент + `README.md` (когда применять, параметры, поведение на мобильных) + `preview.png`.
- Анимации: пресеты подключаются атрибутами (`data-motion="reveal-up"`, `data-motion-delay`), у каждого есть фолбэк для `prefers-reduced-motion`.
- Брейкпоинты по умолчанию: 1440 / 1024 / 768 / 375.
- Именование фреймов в Figma: `NN-Section / vN / desktop|mobile`, раскадровки: `motion / NN-Section / step-N`.

## Проверка перед завершением задачи

- Сборка проходит, в консоли нет ошибок.
- Скриншоты на 4 брейкпоинтах сверены со скриншотами из `design/`.
- Анимации работают и корректно отключаются при reduced motion.
- Spec и `DECISIONS.md` обновлены, если что-то поменялось.

## Роли агентов (вводятся постепенно)

| Роль | Задача | Статус |
|---|---|---|
| Оркестратор | главная сессия: spec + бэклог → задачи, мёрж | сразу |
| Extractor | Figma → `design/` + черновик spec | этап 1 |
| Section builder | одна секция за задачу, из библиотеки | этап 3 |
| Motion | пресеты анимаций, новые эффекты по раскадровке | этап 3 |
| QA | отдельный контекст: Playwright-скриншоты, консоль, a11y, Lighthouse → задачи в бэклог | после пилота |
| Librarian | забирает новое из проекта в стартер | после пилота |

Описания ролей держим нейтральными (markdown), чтобы они работали и как сабагенты Claude Code, и как инструкции для Codex.
