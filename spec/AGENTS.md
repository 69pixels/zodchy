# spec/ — правила для агентов

Общие правила — в корневом `AGENTS.md`. Здесь только то, что касается этой папки.

## Что здесь
Spec проектов: `spec/<проект>/site.md` + `spec/<проект>/sections/NN-<имя>.md`. Шаблоны — `templates/spec/`.

## Правила
- Spec — контракт. Реализуем то, что описано. Не хватает информации — дописываем черновик и ставим `TODO(human)`, не додумываем молча.
- Новый spec и правки — только по шаблонам из `templates/spec/` (те же заголовки, тот же порядок).
- В поле «Вариант из библиотеки» — существующий вариант из `src/sections/` или `NEW`. Для `NEW` указываем имя-кандидат.
- Node-id Figma пишем всегда; если id не снят, ставим `TODO(human)`, а не пропускаем поле.
- Решение, отличающееся от spec, фиксируем в `DECISIONS.md` и обновляем spec в том же коммите.
- Не меняем контент и тексты клиента «для красоты»: источник текстов — Figma или данные проекта.

## Кто что делает
- Extractor: черновик spec из Figma и кода.
- Оркестратор: сводит spec и бэклог в задачи.
- Section builder: читает spec секции, не правит её (только предлагает правки через `TODO(human)` или в задаче).
- Человек: закрывает `TODO(human)`.

## Чего не делать
- Не удалять `TODO(human)`, пока человек не ответил.
- Не копировать длинные тексты в spec: ссылка на источник (`data.js`, Figma) и количество элементов достаточно.
