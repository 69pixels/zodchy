# DECISIONS — решения по системе Zodchy

Формат: дата · решение · почему. Решения по конкретным проектам — в `spec/<проект>/DECISIONS.md`.

## 2026-11-05

- **Бэклог — GitHub Issues** (пока задачи ведём в `backlog/BACKLOG.md`). Репозитории на GitHub, задачи связываются с ветками и PR, агенты работают через `gh`. Linear — если появятся клиентские доски.
- **Анимации — GSAP + ScrollTrigger.** Секции Astro без React, пресеты на `data-motion` — обычный JS. Простые reveal — CSS / IntersectionObserver. Motion заточен под React.
- **Хостинг превью — GitHub Pages сейчас, Cloudflare Pages к пилоту.** Pages даёт один сайт на репозиторий, превью на ветку не получится.
- **Пилот — Ular** (дизайн утверждён, есть мобильная версия); **Spadafy** — проверка переиспользуемости после утверждения десктопного дизайна.
- **Тема Graphical** лежит в репозитории (`starter/theme-graphical/`) как источник атомов; бренд-токены проектов — отдельный слой. Шрифт темы (Inter) — для wireframe; бренд-шрифты подключаются в `brand`-теме. `TODO(human)`: подтвердить.
- **Вложенные `AGENTS.md`** в `spec/`, `design/`, `audit/` (10–20 строк). Агентов «по папкам» не заводим: роли определяются действием (см. корневой `AGENTS.md`).
- **Проектные артефакты** (`audit/`, `design/`, `spec/` по проектам) пока лежат в системном репозитории. При старте стартера (Z-030) переносятся в репозитории проектов.
- **Планшет (768–1023)** отдельного макета не получает: берёт мобильную раскладку (решение по Ular, принимаем как правило по умолчанию).
